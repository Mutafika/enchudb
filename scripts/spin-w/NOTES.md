## 形

entry (32 B、 page をまたがない。 flags を先頭に置き最後に書く):

| off | 欄 | |
|---|---|---|
| 0 | flags (8 bit) \| 深さ (24 bit) | VALID / OBSERVED (遅くとも) / FIRST / DELETE / BASE (宣言の時の値) / VOID (突き合わせで捨てた) |
| 4 | eid (世代 \| 場所) | identity |
| 8 | prev (位置 + 1) | 同じ identity の 1 つ前 |
| 12 | jump (位置 + 1) | skew binary の飛び糸 (Myers 1983)。 FIRST の entry では前の住人の最後の entry |
| 16 | 時刻 | WAL の HLC を詰めた数 (wall ms << 20 \| logical) |
| 24 | 値 | u64::MAX = 値が無い (untie / 削除) |

- 時刻 = 変更時刻 (`history::pack(hlc)`) + 更新の回数 (深さ = その identity のその列の何回目の entry か、 宣言の時の値 / 最初 = 0)。 どちらでも引ける
- 同じ書き込みは (identity, 列, 時刻) で 1 つ: 足す前に鎖で同じ時刻を探す (時刻の順の鎖なので飛び糸で O(log n))
- 値が変わらない書き込み (書き直し) は変更ではないので足さない (更新の回数は変更の回数)
- デッキ (`pull_at`): 値ごとの差分の並び (時刻, 入った/出た, eid) を、 その値を最初に見た時に entry を全部なめて作り、 後は書き手が足す。
  見ていない値は並べない (書き手は 「見た値があるか」 の読み 1 回)
- 場所が使い回されたら、 次の住人の最初の entry の飛び糸が前の住人の最後の entry を指す。 古い eid で読むと場所の鎖を住人ごとに飛んで探す

## 決めたこと (3. 時刻の無い道)

最初は 「ユーザの書き込みは断る」 にしたが、 WAL は任意 (WAL なしで開くアプリも普通に在る) なので、 ユーザと話して **案 2** に変えた:

- **WAL の無い session のユーザの書き込みは engine の時計** (`HistCol::now`: 壁時計の ms と、 列の時計 (見た最大) + 1 の大きい方)。 印は付けない
  (その書き込みの時刻として正しい)。 `open_standalone` / build phase / schema の `Database::open` でも履歴の列に書ける。 WAL が無いので電源断の後の
  足し直しは無く、 履歴は本体と同じく書き出した所まで (開く時の cell との突き合わせは効く)
- WAL を付ける時 (`spawn_consumer_with_oplog`、 WAL の付く道は全部ここを通る) に WAL の時計を履歴の時計より先へ進める (`observe_history_clock`):
  列の時計が壁時計より先に出た後で WAL 付きで書いても、 同じ行の時刻が戻らない
- **engine の中の時刻の分からない道は 「遅くとも」 の印 (`OBSERVED`)**。 呼び手は `HIST_NO_TIME` (`Hlc::ZERO` と分ける印の値) を渡す。 開く時の
  後始末 (gen.seg の突き合わせで完了させた死 `drop_leftover_cells`、 ring の死んだ場所)、 sync の畳み・改名の分け (sync する DB は宣言を断るので今は
  通らない)、 開く時の cell との突き合わせ。 時刻は列の時計で、 意味は 「遅くともこの時刻にはこうなっていた (本当の変更はそれ以前)」。 読みは、
  答えた entry の次がこの印なら `uncertain` を立てる。 向きはこのまま (変更の時刻の上限) で解決済み: 下限は鎖の 1 つ前の entry の時刻で、 「(前の時刻, この時刻] のどこかで変わった」 が表せている (2026-11-27 ユーザの決定)
- 前の住人の削除を突き合わせで足す時は、 時刻を次の住人の最初の時刻にして印を付ける

## 電源断の後 (7.)

門に頼らず開く時に揃える:

1. 再生の前: entry をなめて鎖と heads を作り直す (`relink`、 header の len より後でも flags の立った entry は拾う。 同じ identity の同じ時刻は 1 つにする)
2. 再生: 書き手の道のとおり entry を足す。 加えて **cell が LWW で弾いた record も履歴に足す** (cell の版数だけ先に届いた像では、 再生が cell を書き直さないので
   書き込みの entry が戻らなかった — 電源断の試験で落ちた)。 Delete の再生も宣言した列ごとに 「消えた」 を足す。 時刻の戻る entry を足したら、 その場所の鎖を
   その場で繋ぎ直す (`relink_slot`)。 時刻の前の値と同じなら足さない
3. 再生の後 (`settle_history_at_open`): 場所ごとに cell と集まりの最新を突き合わせる。 cell が正しい。 **entry は外さず、 足すだけ**
   (entry だけ届いた書き込みも手元で在った書き込み。 下の 2 つは前の形で、 外す方は書き出しをしない像で、 使い回しで消えた版数や別の住人の値を
   基準に、 書き出しの済んだ entry を外した (25 回に 1 回ほど)。 今は cell の値を 「遅くとも」 で 1 件足す。 時刻は cell の版数が最新の entry より
   後ならそれ、 でなければ時計):
   - 版数のある DB: cell の版数より新しい entry は cell に届かなかった書き込み → VOID。 残りの最新が違えば cell の版数の時刻で 「遅くとも」 を足す
     (始めは印なしで足していた。 書き出しをしない像で、 版数だけ届いた cell (#705 の形) に別の書き込みの版数の時刻を付け、 在らなかった書き込みを作った)
   - 版数の無い DB: cell と同じ値の一番新しい entry より新しい entry を VOID。 無ければ 「遅くとも」 で足す
   - 死んだ場所の最後の行 / 前の住人の最新に値が残る → 削除の 「遅くとも」
   - VOID を出したら全体を繋ぎ直す
- 突き合わせは表の場所を全部見る (O(容量)) が、 きれいに閉じなかった後だけ

## 測りの直し (書き手の道)

最初の形 (heads も segment、 entry を読んで最新を決める) は、 宣言した列の書き換えの上乗せが **+500〜1000 ns** だった。 測り方も揺れが大きく
(宣言の無い列の書き換えだけで 650〜1080 ns)、 20 万回ずつ 5 組では差が取れない (`note` を飛ばしても −866〜+1065)。 2 万回ずつ 60 組の差の中央値に
直した (飛ばすと 0〜23 ns)。 中を測った内訳と直し:

| 内訳 | 直し |
|---|---|
| 最新の entry を読む (乱れた場所 ~190 ns) + 飛び先を決めるのに entry 2 つ | heads に最新の entry の写し (32 B) を置き、 entry を読まない。 飛び先の深さは深さだけで決まる (d − skip_gap(d)、 規則と 20 万段で一致を確かめた) ので、 幅が揃う時だけ 1 つ読む |
| heads の page が書き出し (msync) のたびに write-protect に戻り、 場所ごとに fault | heads を memory に (閉じる時だけ file に置く) |
| 時計の SeqCst の fetch_max | 外した。 時計は末尾の entry から読む。 差分の並びを作る側との約束は場所を取る len の SeqCst の RMW に寄せた |
| デッキを見た後: 差分の並びの二分探索 (cold な 16〜32 KB を 10 回ほど、 1 回 1.7 µs) | 末尾だけ見て足す。 表の hash を SipHash から u64 の掛け算に |
| 時点 t のデッキ: 毎回 prefix を並べ替え | 後ろから読み、 初めて見た eid だけ決める (開番地の小さな表)。 今の時点は円柱を読む |

## 線を外れた所と見立て

- **宣言した列の書き換え +250 ns (線 +80)**。 残りの大半は heads の 1 行 (32 B) を読んで書く cache / TLB の外れ 1 本 (この VM で 100〜130 ns、
  時点 t の 1 行 ~300 ns = 外れ 2〜3 本と同じ桁) と、 entry の segment の伸び・dirty の印。 場所ごとの最新を別の配列に持つ限り、 乱れた行への
  書き換えは 1 本の外れを払う。 前の試作の +13〜33 ns は球を memory の上に置き、 書き換えの行が近かったのではないか (要確認)。 下げるなら:
  最新の位置を列の cell の横に置く (列の形を変える) / 書き手ごとに entry を溜めて後でまとめて heads を直す (読みは溜めも見る)
- **デッキを見た後 +880 ns**。 見た値の差分の並びの末尾 2 つ (古い値・新しい値) が cold な memory。 値の数 (1000) ぶん並びを持つと、 乱れた
  書き換えのたびに外れ 2 本 + hash 表。 値をすべて見た時の上限に近い測り (`pull_at` を 1000 値とも呼んだ後)。 下げるなら: 並びを値ごとでなく
  時刻の区間ごとの控え (snapshot) にする / 書き手は区間の末尾に足すだけにして、 値で分けるのは読みの時
- 宣言の無い DB の数は v0.38.0 と揺れの内 (書き手の道に足したのは atomic の読み 1 回)。 ただし VM の揺れが ±10% あるので、 1.03 倍の線は
  この測りでは見分けられない。 静かな機械で取り直すこと

## 決めずに置いた所

- 3. は案 2 (上)。 印の向き (変更の時刻の上限) は解決済み (上)
- 値が変わらない書き込み (書き直し) は entry を足さない (更新の回数 = 変更の回数)。 書いた回数を数えたいなら足す形に変える (disk が増える)
- 宣言は書き手の居ない時に (宣言の時の値をなめる間に書かれると順が前後する。 試作では確かめていない)
- 時刻の戻る entry を足した時の場所の繋ぎ直しは、 その間の読み手に途中の糸を見せうる (通るのは開く道の再生・突き合わせだけ)
- readonly で開いた process は、 heads の file が合わない (前の session がきれいに閉じていない) と繋ぎ直せず、 その process の読みは履歴を持たない
- 時刻の詰め方は logical を 20 bit に切る (1 ms に 100 万 record を越えると同じ時刻になり、 重複として落ちる)
- `copy_to` / `snapshot_export` は `hist/` を写さず、 写した `tables` に HIS1 も書かない (写し先は宣言なし)
- packed / wasm: 宣言を断るが、 `history` module は wasm で build しない (engine の欄が参照するので wasm の build は今は通らない)。 Windows も heads が
  libc の mmap なので通らない
- `drop_history` は file を消す。 同じ列に宣言し直すと地平から始まる

## 次の切れで要ること

- 書き手の上乗せを線に入れる形 (上の 2 案)。 書き手 8 本の測り (この VM では取らない)
- sync する DB: 受けた書き込みの時刻は author の HLC (peer が入る)。 時刻の詰め方に peer を入れる (今は (wall, logical) だけ = 自分の書き込みの間でしか一意でない)、
  LWW で負けた書き込みも履歴には在る (どちらを本体とするか)、 wire / 要約での合わせ
- 名前の束ね (pkformer) を履歴の上で置き換える: 名前の列の履歴 = 名前の年表
- Leaf の列 (slot の使い回し) / 語を回収する DB の Tag の列 (番号の使い回し): 値を entry に写す形 (中身か語の世代)
- 残す長さ (今は全部残す。 1 回 32 B + 場所 32 B) と、 捨てた所より前の地平
- 位置の半分 (ひねり)
- デッキの差分の並びを最初に作る時に entry を全部なめる (240 万で 24 ms)。 値の数が多い列は控えを持つか、 書く時に並べるか

## 変異の 3 回目 (案 2 の後、 `mutate-run3.txt`)

20 本: **17 落ち / 3 生き残り**。 書き出しをしない像の試験は 25 回続けて落ちない (`nosync-25.txt`)。

- 重複落としを外す: 等価。 再生の重複はその時刻の entry と同じ値なので 「前の値と同じなら足さない」 で必ず落ちる (2 回目に落ちたのは、 突き合わせが
  entry を外していた頃の絡み)
- WAL を付ける時に WAL の時計を進めない: 効くのは列の時計が壁時計より 1 ms 以上先に出た時だけ (1 ms に 100 万回書く / 壁時計が戻った)。 試験の
  5000 回では 0.005 ms しか先に出ず、 時計を差し込む口が無いので作れない。 **試験の穴として残す** (時計を差し込む口を作れば落とせる)
- engine の中の道を 「遅くとも」 にしない: 今の範囲で通るのは開く時の後始末だけ。 印の値 (時刻 1) で足そうとすると 「前の値と同じ」 で落ち、 その後の
  突き合わせが同じ死を 「遅くとも」 で足す = 今の範囲では等価 (sync の畳みが入ると等価でなくなる)

## 書き込みの上乗せの 2 案 (2026-11-27、 `cmp-run1.txt`、 `examples/spin_w_cmp.rs`)

- **案 A** (宣言した列の書き換え +250 ns への案): 「書き手ごとに溜めて後でまとめて heads を直す」 形にした。 書き手は heads を読まず、 書く前の cell の
  値で 「変わったか」 を決め、 entry を糸なし (`PEND`) で足して位置を溜める。 溜めが 1024 に届いた書き手か読み手がまとめて繋ぐ (heads を 8 つ先読み)。
  読み・開く道・閉じる時は先に溜めを繋ぐ。 「最新の位置を列の cell の横に置く」 は列の segment の形 (u32 の cell の並び、 engine 全体で共有) を
  変えることになり、 一切れでは作っていない
- **案 B** (デッキを見た後 +880 ns への案): 書き手は値ごとの差分の並びを保たない。 読みは今の円柱から t より後の差分を戻す。 差分は閉じた区間
  (4096 / 65536 entry) ごとに読みの時に値で並べて控え、 開いた末尾はなめる
- 切り替えは列ごとの実行時の旗 (`Engine::history_set_modes`、 既定は環境変数 `ENCHU_HIST_WRITE=batch` / `ENCHU_HIST_DECK=blocks`)。 同じ DB の中で
  形を回し、 宣言の無い同じ形の列との差を 2 万回 × 60 組の中央値で取る。 案ごとに別の commit にはできていない (同じ関数に旗で入れた、 30f0e01)
- 正しさ: spin_w_history (crashsim 込み 8 本) は 4 つの形 (今 / A / B / A+B) とも通る。 単体試験で、 今の形の列と案の列に同じ 15 万回 (場所の使い回し込み、
  B の大きい区間 2 つ + 小さい区間 + 末尾、 A の溜めを何度も越える) を当てて、 時点 t の値とデッキが同じ。 案ごとの変異はレビューの直しの後に回す

見立て:

- **案 A は乱れた行に効く** (見る前 −100〜−130 ns、 見た後 −70〜−110 ns)。 heads の外れを並べて重ねられる。 熱い行は +20〜+40 ns 悪い (溜めの mutex と、
  heads が cache に居るのに後で読み直す分)。 それでも乱れた行は +140〜+210 ns で、 線 (+80) には入らない。 残りは cell の 2 度目の読み・entry の
  segment への書き・溜めの mutex
- **案 B は書き手のデッキの上乗せを消す** (熱い行 182 → 76 ns) が、 **読みが使えない**: t より後の差分を全部戻すので、 書き込みの多い列では 1 回の
  デッキが 0.8 ms (値 1000 種)〜1.2 秒 (値 10 種)。 区間に 「区間の終わりの時の値ごとの束」 を控える (値を戻す差分を区間 1 つ分に抑える) 形にしないと
  線の 30 µs に届かない。 その控えは値の少ない列では束そのものが大きい (10 万行 × 区間の数)
- **今の形のデッキの読みも、 書き込みの多い列では線を越える** (1 値あたり差分 1.5 万件をなめて最後の差分を決める = 150 µs)。 前の測り (変更が少ない列) の
  20 µs は差分が少なかったから。 値ごとの並びにも区間ごとの控え (時点の束) が要る
- どちらの案も一切れの線 (+80 ns / 30 µs) を両方は満たさない。 線を決める材料: 乱れた行の上乗せ下限は A で約 +150 ns (この VM)、 デッキの読みは
  控えの形を決めないと線が立たない
